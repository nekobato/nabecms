# 認証メール

招待やパスワード再設定のリンクを受信箱へ届ける場合に、認証メールを使います。
送信には Cloudflare Workers Paid と、Email Sending に登録した送信ドメインが必要です。
招待リンクはメールを設定せずにコピーして共有することもできます。

## 送信環境を設定する

`wrangler.jsonc` に Email Sending をバインドし、配備先の環境に送信元アドレスと公開 URL を設定します。
名前付き環境を使う場合は、対象の環境にバインディングと変数を指定します。

```jsonc
{
  "send_email": [
    {
      "name": "EMAIL_SENDER",
      "allowed_sender_addresses": ["no-reply@example.com"]
    }
  ],
  "vars": {
    "AUTH_EMAIL_FROM": "no-reply@example.com",
    "AUTH_EMAIL_BASE_URL": "https://cms.example.com"
  }
}
```

`AUTH_EMAIL_FROM` と `allowed_sender_addresses` で送信元をそろえます。
`AUTH_EMAIL_BASE_URL` には受信者がリンクを開く HTTPS オリジンを、パスを含めずに指定します。
ローカル開発に限り、localhost の HTTP を使えます。

## Admin UI で有効にする

バインディングを配備したら、Super Admin で「Settings → Email」を開きます。
表示名を保存し、招待メールとパスワード再設定のうち利用する機能を有効にします。
初期状態ではどちらも無効です。
送信元と公開オリジンは配備時の設定を使います。

同じ画面でテスト送信を実行すると、保存済みの設定で操作中の管理者宛てに送信します。
成功表示は Cloudflare が送信を受け付けたことを示します。
テストメールが受信箱に届くことを確認します。
テスト用のアドレスに招待を送るか、テスト用アカウントのパスワード再設定を要求します。
届いたリンクから配備先の画面を開けることを確かめます。
直近の結果には用途、状態、時刻、エラーコードを記録し、本文、宛先、トークンは記録しません。

## 招待を送る

招待を作成するときにメール送信を選べます。
送信に失敗した場合は、招待一覧から同じリンクを再送するか、コピーして共有します。
招待が有効で、未使用かつ期限内であれば、同じリンクを利用できます。

`JWT_SECRET` を変更した場合や、再送に必要な情報を持たない招待では、送る前にリンクを再生成します。
再生成すると以前のリンクは失効します。
招待で付与できる権限は[招待の規則](./security.md#招待-invites)を参照します。

## パスワードを再設定する

機能を有効にすると、ログイン画面から再設定メールを要求できます。
アカウントの所有者は、発行から 1 時間以内にリンクを開いてパスワードを設定します。
パスワードをまだ設定していない既存ユーザーも利用できます。
要求時の応答は、アカウントの有無やメールの送信結果によって変わりません。

別のメールを要求したり、新規の要求を無効にしたりしても、発行済みのリンクは有効期限まで使えます。
再設定に成功すると、そのユーザーの再設定リンクとセッションはすべて失効します。
新しいパスワードでログインし直します。
リクエストの形式は[Admin API の認証メール](./api/admin.md#認証メール)を参照します。
