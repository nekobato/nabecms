# Admin UI ガイド

管理画面では、コンテンツの項目を定義し、記事を編集して公開します。
編集や公開を担当するユーザーの権限もここで設定します。
最初の管理者を作成する手順は[クイックスタート](../getting-started.md)に記載しています。

## ログインとセッション

`/admin/` を開き、メールアドレスとパスワードでログインします。
長時間操作していない場合や、権限の変更でセッションが失効した場合は、もう一度ログインします。
パスワード再設定をメールで受け付けるには、[認証メール](../email.md)を設定します。

## モデル設計

記事や製品など、コンテンツの種類ごとに「Models」でモデルを作成します。
記事であれば、一覧に出す見出しに `text`、本文に `rich_text` を使えます。
翻訳ごとに値を持たせる項目には `hasLocales` を、Contents API で配信しない項目には `isPrivate` を設定します。
入力条件と型の選択肢は[フィールド定義](./fields.md)を参照します。

モデル名と説明はヘッダーの「編集」で変更します。
フィールドをドラッグして並べ替えたら、適用するか元に戻します。
モデルを削除するとエントリー、フィールド、リビジョンも削除されるため、既存のデータがある場合は[変更の影響](../data-management.md#破壊的変更の影響)を確認します。

## エントリー運用

「Contents」でモデルを選び、エントリーを作成します。
配信前に編集内容を確認するには下書きを使い、配信を始めるときは「Publish」を選んで確認します。
履歴から過去の版を復元すると、新しい下書きができます。
公開中の内容は、次に公開するまで維持されます。

一覧では表示タイトルかエントリー ID で検索できます。
主列はモデルの表示タイトルで、値が空ならエントリー ID になります。
「Columns」で表示する列を選び、Sheet View の列見出しで並べ替えます。
選択したロケールに値がなければ、既定ロケールの値を使います。

### 関連エントリーの閲覧と編集

選択済みのリレーションやリッチテキスト内の参照を開くと、関連エントリーの編集画面が表示されます。
移動した経路はパンくずで確認できます。
前のエントリーに戻っても入力は保持され、経路から外れたエントリーは「未保存の変更」から再開できます。
同じエントリーを再び開くと、その編集状態に戻ります。

保存や公開の対象は表示中のエントリーです。
関連先に保存した変更は、元のエントリーの変更とは別に確定します。
ダイアログを閉じるときは、関連先の未保存の入力のうち破棄するものを選びます。
元の画面の入力は残ります。
ページを離れたり再読み込みしたりする場合は、開いたエントリー全体の未保存の変更を確認します。
未保存の入力を保持するのは、現在のページを開いている間です。

参照先を取得できない場合は、元の編集画面に戻れます。
保存に失敗した場合は入力を保持します。

## メディア管理

「Media」でファイルを選ぶか、アップロード領域へドラッグします。
複数選択した場合、管理画面は一つずつ送信します。
一覧では種別で絞り込み、寸法やサイズを確認できます。
利用できる形式とサイズは[アップロード要件](../api/admin.md#運用メモ)を参照します。

画像の派生版を作るテンプレートがある場合、アップロード時はすべて選択されています。
不要なテンプレートは選択を外します。
`fit: cover` は指定した領域を満たすよう切り抜き、`contain` は画像全体を収めます。
`upscale: false` では元画像より大きな派生版を作りません。
ファイルを削除した後の扱いは[メディアの運用](../operations.md#メディアの運用)に記載しています。

## ロケールと言語

「Settings → Locales」で既定ロケールを設定します。
翻訳する項目は、フィールドの値をロケールごとに保存します。
メディアは共通なので、別の言語から同じファイルを使うことも、別のファイルを選ぶこともできます。

## ユーザーと権限

「Roles」でロールを作成し、「Users」で割り当てます。
エントリーでは Create、Read、Update、Delete、Publish、その他のリソースでは Read と Write を選びます。
この画面で設定したエントリー権限は全モデルに適用されます。
モデルを指定する権限の形式は[Admin API](../api/admin.md#認可モデル)を参照します。

新しい利用者を通常ロールで招待します。
付与できるロールは[招待の規則](../security.md#招待-invites)に記載しています。
既存の利用者のロールは「Users」で編集します。
メールアドレスはユーザー編集権限を持つ本人が変更し、パスワードは本人が[再設定メール](../email.md#パスワードを再設定する)から変更します。

## API Keys

「API Keys」で配信用のキーを発行し、少なくとも一つの権限を選びます。
連携先に特定のモデルだけを許可する場合は `allowedModels` を設定し、一覧で許可したモデル名を確かめます。
キーの入れ替え時は連携先を新しいキーに切り替え、旧キーを失効させます。

## ログの閲覧と検索

`logs:*:read` を持つ利用者は「ログ」で操作ログ、エントリーのリビジョン、認証結果を確認できます。
操作ログは期間、操作、対象 ID、認証結果は期間、結果、利用者 ID で絞り込みます。
ID は完全一致です。
日付はブラウザーのタイムゾーンで扱い、終了日の終わりまでを含めます。

「検索」で条件を適用し、「クリア」で解除します。
条件とページ位置はタブごとに保持します。
操作ログで変更前後の状態やリビジョン ID を確認し、本文が必要ならリビジョンから対象エントリーを開きます。

## 設定

「Settings」では稼働中の NabeCMS のバージョンとレコード数を確認できます。
データを取り出す手順は[データ管理](../data-management.md#他cmsへの移行用エクスポート)、招待と再設定のメールは[認証メール](../email.md)を参照します。

## ログ管理

Super Admin は「設定 → ログ管理」で操作ログと認証ログの保持期間をまとめて設定します。
既定は 90 日で、1〜730000 日の整数または無期限を指定できます。
変更は次回の定期処理で反映されます。
期間を短くする場合は、削除対象になるログの範囲を確認してから保存します。

状態を取得すると、直近の開始、終了、成功日時、削除件数、期限切れログの残存を確認できます。
初回の実行待ち、48 時間以上実行を確認できない状態、15 分のリースを過ぎても終了が記録されていない状態は区別されます。
Cron を設定した直後も、初回の実行までは待機中と表示されます。

削除に失敗した場合はエラーコードをデプロイ管理者に伝え、[ログの定期削除](../operations.md#ログの定期削除)の手順で調べます。
データベースに接続できない間は、最後に取得した状態が表示されます。
